# 仓库约定

给以后加项目的自己看。

## 加一个新项目

1. 在 `apps/` 下建目录，目录名用英文小写加连字符，比如 `apps/homework-miniprogram`。
2. 项目自己的说明写在 `apps/<项目>/README.md`：做什么、怎么跑、依赖什么、已知限制。
3. 不要在 `apps/` 里放跨项目的公共代码。真有共用逻辑，抽成独立目录，不要互相 require。
4. 根 README 的项目表补一行。

## Skill 放哪

跨项目能复用的放 `skills/`，只服务单个项目的放 `apps/<项目>/skills/`。判断标准很简单：换一个项目还用得上，就放根目录。

每个 Skill 一个目录，主文件固定叫 `SKILL.md`，需要配图和长文档时放 `references/`，与 Skill 一起复制才能用。

## 数据红线

仓库是公开的。下列内容任何情况下都不进仓库：

- 真实校名、院部名、校内文号、通知原文。
- 真实班级、学号、姓名、成绩、手机号、邮箱。
- 真实课表导出文件与成绩单导出文件。
- 任何从教务系统抓下来的原始页面或截图。

`.gitignore` 已经拦了表格与导出 json。绕过它用 `git add -f` 之前先想清楚。

新项目的示例数据统一用虚构名，课程用通用名，教室用 `1-101` 这种通用编号，班级用 `25示例1班` 这种格式。

## 提交信息

一句英文，祈使句，说清做了什么。比如 `add exam countdown page`、`fix pane width on first render`。一次提交只做一件事，不把格式化与功能混在一起。

## 版本与发布

小程序在 `project.config.json` 里改版本号，提交前跑一次编译。发布包不包含私有配置，`project.private.config.json` 已在忽略列表里。
